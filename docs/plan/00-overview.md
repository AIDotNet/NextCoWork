# 00 · 总览与关键决策

## 1. 目标

1. **3.0 客户端原生化**:Avalonia 12(≥ 12.1.5,< 13)+ .NET 10 + TKCode.Arc(锁定 `1.1.0-preview.6`)。
   一套代码覆盖 macOS / Windows / Linux / iOS / Android。浏览器(WASM)先不做,但架构上不堵死。
2. **Agent 运行时单独设计**:Agent 是一个可以单独部署的服务,对客户端类型无感知。
   桌面、手机、平板、以后的网页和 CLI 都是它的「控制端」,地位相同。
3. **移动端可用**:手机上能看项目和会话、发消息、审批、看子代理、看 diff、停止运行,并且能收到推送。
4. **2.x 用户能平滑升级**:已经装了 2.x 的用户通过现有的自动更新收到 3.0 并完成安装。数据(会话、项目、
   供应商密钥、设备配对)原地保留,不需要手动导出导入。
5. **界面重新设计**:不参考 2.x 的界面。采用「项目栏 + 项目面板 + 工作区」三栏布局,项目可以分组。

## 2. 非目标(3.0 不做)

- **不用 C# 重写 Agent 内核**。2.x 的内核(`src/main/kernel`)和无界面设备服务(`src/agent/server`)
  已经有完整的工具链、权限、子代理、MCP、Skills 和持久化,重写的风险和工期都不可控。
  3.0 只把它整理成一个独立的运行时。是否改用 C# 实现,到 3.x 再按需评估。
- 不在手机上运行 Agent。手机只做控制端(理由见 [02](02-agent.md#移动端约束))。
- 2.x 的插件 React 视图、内置浏览器、Office 编辑器不保证在 3.0 GA 时全部对齐,
  分期计划见 [05 功能对齐矩阵](05-roadmap.md#2-功能对齐矩阵)。

## 3. 关键决策(ADR)

| # | 决策 | 理由 | 备选及否决原因 |
|---|---|---|---|
| D1 | 客户端和 Agent 分成两个进程,中间只走「设备协议」 | 移动端只能做远程控制端。本机和远程走同一条路径,移动端就不需要额外开发 | 桌面端把内核嵌进客户端进程:本机一套、远程一套,两套逻辑必然产生分歧 |
| D2 | 桌面端安装包内置本机 Agent(sidecar),用回环地址加本机令牌连接 | 用户感知不到多了一个进程,开箱即用 | 让用户自己装设备服务:门槛太高 |
| D3 | 3.0 的 Agent 运行时继续用 TypeScript/Node,内置 Node 运行时 | 复用经过验证的内核,把精力放在客户端 | 用 C# 重写:见非目标 |
| D4 | 协议定义只有一个来源:`protocol/` 下的 schema,用它生成 TS(zod)和 C# 类型,两边共用一套「黄金向量」测试 | 两种语言并存,手工同步一定会漂移 | 手写两份:否决 |
| D5 | UI 用 TKCode.Arc,但业务视图只引用我们自己的薄封装 `Ncw.UI.*` | Arc 还是 preview 版本,封装一层可以隔离它的破坏性变更 | 业务视图直接用 Arc:升级时改动面太大 |
| D6 | MVVM 用 CommunityToolkit.Mvvm,不依赖反射,兼容 NativeAOT 和裁剪 | iOS 必须 AOT,桌面端也希望启动快 | ReactiveUI:较重,依赖反射的地方多 |
| D7 | 状态统一管理规则在 C# 里照搬(见 [01 §5](01-architecture.md#5-状态统一管理c-版)) | 2.x 踩过的「四份状态互相打架」不能再来一次 | — |
| D8 | 2.x → 3.0 经过「桥接版本 2.9」:2.9 负责数据交接,并自己安装 3.0 | 不依赖 electron-updater 在各平台的内部行为(Squirrel 签名校验、NSIS 参数) | 直接把 3.0 安装包塞进 electron-updater 的 feed:macOS 上有签名校验风险,也没法在交接前整理数据 |
| D9 | 3.x 的自更新用 Velopack | .NET 生态里成熟的方案,三个桌面平台都支持,有增量包和通道,feed 是普通的静态 HTTP | 自研更新器:不划算 |
| D10 | 项目分组属于「用户布局」,通过账户配置同步;项目本身(工作区)的事实由 Agent 持有 | 分组可能跨设备(本机项目和 NAS 上的项目放在同一组),手机上也要看到同样的分组 | 分组存进某个 Agent:跨设备的项目无处安放 |

## 4. 术语

| 术语 | 含义 |
|---|---|
| **Agent 运行时 / ncw-agent** | 持有数据库、工作区、Git、终端和模型调用的服务进程,源自 2.x 的 `src/agent/server` |
| **控制端(Client)** | 连接 Agent 的界面程序:3.0 桌面端、手机端,以后还可能有网页端和 CLI |
| **设备(Device)** | 一个 Agent 运行时实例。桌面内置的那一个叫「本机」 |
| **项目(Project)** | 某台设备上的一个工作区(目录)。界面上的一个项目图标对应一个 `(deviceId, workspaceId)` |
| **项目组(Group)** | 用户对项目的分组,纯布局数据 |
| **会话 / Run / 子代理 / 交互** | 沿用 2.x 的定义。交互指待处理的审批、提问等 |
| **设备协议** | 控制端和 Agent 之间的 RPC、事件流、端到端加密协议,源自 2.x 的 `src/shared/device` |
