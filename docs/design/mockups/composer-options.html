输入框重设计 · 4 个方案

每个方案都能点:模型 / 思考 / 权限 / 附件弹层都是真的。用上面的工具条切换「场景」(空、输入中、运行中、附件与引用、斜杠命令)和「宽度」(桌面 / 手机 compact),颜色名对齐 Arc token。模型数据是假的,能力字段对应现有的 ModelChoice(供应商、别名、上下文窗口、视觉、思考、是否可用)。

方案 A

精修单卡

保留现有结构,只解决视觉问题 —— 改动最小

改了什么

  • 去掉内层边框:现在是卡片套输入框两层圆角框,改成一张卡,焦点时整卡描边。
  • 模型带供应商标识,下拉按供应商分组、可搜索,行内显示上下文窗口 / 视觉 / 思考。
  • 思考档位用刻度条替代「思考:最大」文字,一眼看出强弱。
  • 权限移到右侧并着色:完全访问是琥珀色,和普通选项拉开。
  • 上下文圆环从状态行搬到发送键旁边(ContextUsageEventDto 已有)。

优点

  • 现有 NcwDropdownMenu 基本够用,只需支持分组 + 搜索头
  • 用户零学习成本

代价

  • 三个下拉仍是三次点击;窄屏只剩图标
方案 B

模型 + 思考合一

一个按钮选「用什么、想多深」,思考档位跟着模型能力走

改了什么

  • 双栏选择器:左边是分组 + 搜索 + 「最近使用」,右边是选中模型的详情和它支持的思考档位。
  • 不支持思考的模型直接说明,不再出现一个灰掉的思考按钮;切模型时档位自动夹到可用范围。
  • 权限降为一个带色点的文字,附件 / @ / / 合并到「+」菜单。

优点

  • 解决「思考档位和模型能力不匹配」的根本问题
  • 工具条最干净,内容区更突出

代价

  • 需要新的 Popup 控件(双栏),NcwDropdownMenu 不够
  • 改档位要先打开模型面板,多一步
方案 C

上下文条

把「在哪执行、能做什么」放到输入框顶上,权限一键切换

改了什么

  • 顶部条:设备 / 项目 / 分支(执行环境标识,和审批卡片一致),右边是权限分段按钮,三档常驻可见。
  • 底部工具条:附件、@、/ 三个显式入口;模型和思考;右侧是上下文用量条(带数字)。
  • 模型下拉是带等宽数字列的紧凑表格,方便比较窗口大小。

优点

  • 权限和执行环境永远可见,安全感最强
  • @ 和 / 有可点击入口,新用户可发现

代价

  • 纵向多占 ~40px
  • 信息密度高,手机上需要折叠
方案 D

极简浮岛

单行胶囊,设置收进一个摘要按钮 —— 手机优先

改了什么

  • 胶囊输入:单行起步,随内容长高;附件 / 引用 / 命令在「+」里。
  • 一个摘要按钮(供应商标识 + 档位刻度 + 权限盾牌)打开「运行设置」面板:常用模型卡片、思考滑杆、权限三选一。
  • 附件和引用浮在胶囊上方,运行状态是一行小字。

优点

  • 手机和窄窗口最舒服,一套布局两端通用
  • 所有运行设置在一个面板里一次调好

代价

  • 桌面上当前模型名不直接可见(只有图标)
  • 设置隐藏得最深
