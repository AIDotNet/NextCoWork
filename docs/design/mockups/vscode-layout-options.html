左侧项目菜单 + 右侧展开文件列表 · VS Code 风格设计方案

基于当前 NextCoWork 3.0 代码（Sidebar.axaml + FilesPane.axaml + WorkspaceArea.axaml），给出 3 套可直接点击体验的完整方案。重点对比左侧项目/会话如何组织与右侧文件树如何借鉴 VS Code Explorer（紧凑工具栏、缩进线、Git 红黄绿语义色、Compact Folders 单目录合并、原位新建、单击斜体预览 Tab vs 双击固定、面包屑）。

为什么要改：当前左、右两侧的 6 个具体问题

左侧
当前项目不显眼、悬停遮挡状态：选中项目仅文字变粗，展开多个项目时分不清右侧文件树属于谁；悬停出 + ⋯ 时直接把待处理数盖没了。
左侧
缺少树缩进线与折叠分区感：全局入口、收件箱、项目树平铺堆叠，项目组 → 项目 → 会话 没有纵向引导线，层级松散。
右侧
头部占掉 110px+，新建藏在二级菜单：大项目名 + 常驻大搜索框挤压了文件树；高频的「新建文件/文件夹」「定位当前文件」没有像 VS Code 一样放在标题行。
右侧
没有缩进线 & Git 颜色全写死黄色：FileRow.axaml 里 M / A / D / U 全部是 Warning 黄色，文件名也不随 Git 状态着色。
右侧
C# 深层空目录没合并、新建弹大模态框：Views/Desktop/Inspector 要点三次；新建/重命名弹居中大 Dialog 打断视线，不如 VS Code 原位输入框顺手。
联动
单击文件直接塞满顶部标签栏：缺少 VS Code 的「单击斜体预览 Tab（复用同一个标签）+ 双击固定」与文件顶部的可点击面包屑（Breadcrumbs）。
方案 A

三栏各司其职 · 全面换装 VS Code Explorer 细节

推荐 · 架构改动最稳 保留「左：项目与会话 ｜ 中：主工作区 ｜ 右：文件检查器」格局，左右两侧内部交互完整对齐 VS Code
💡 试试交互：① 左侧点折叠分区（待处理 / 项目 / 定时任务）、点项目切换右侧文件树、悬停项目看 + ⋯ 不遮挡角标；② 右侧悬停 NEXTCOWORK 标题点「新建文件（原位输入）」「定位当前文件」「紧凑目录开关」「放大镜筛选」；③ 单击文件看顶部斜体预览 Tab 复用，双击文件固定 Tab，点面包屑或点「+ 引用到对话」。

核心设计要点

  • 左侧变成 VS Code 折叠面板（Accordion）：顶部紧凑 [+ 新会话 ⌘N] [⌕ ⌘K]，下方三个标准折叠区 待处理 (3)、项目（悬停出新建项目 / 新建组 / 全部折叠）、定时任务。
  • 项目树强化：当前项目带左侧强调色竖条 + 浅底色；展开的组和会话带纵向缩进引导线；悬停出 + ⋯ 时角标左移不消失。
  • 右侧 1:1 还原 VS Code Explorer 体验：24px 分区头悬停浮现 新建文件 / 新建文件夹 / 定位当前文件 / 刷新 / 全部折叠 / 筛选；搜索框按需展开；支持 Compact Folders（如 Views/Desktop 合并一行）、原位输入框、Git 红黄绿着色。
  • 标签栏联动：单击文件复用斜体 Preview Tab，双击固定；文件页顶部带可点选的 Breadcrumbs 面包屑 + 一键 @引用到对话。

优势

  • 会话与文件树同屏可见：边和 AI 聊边看右侧哪些文件变绿/变黄、随手单击预览代码，不用来回切面板。
  • 完全符合现有 Store / ViewModel 分工：SidebarViewModel 与 FilesPanelViewModel 原位升级，NcwTreeView 本身已内置 ShowIndentGuides。
  • 空间利用率提升 ~30%：右侧去掉 70px 冗余头、行高 25px，一屏多看 6–8 个文件。

注意点与工作量

  • 1440px 以下窄窗口右侧检查器仍是抽屉覆盖（保持现有响应式断点）。
  • 工作量约 3–4 天（改 03-ui-layout.md → 左侧 Accordion & 缩进线 → 右侧紧凑头/Git 着色/Compact Folders/原位输入 → Preview Tab & 面包屑）。
方案 B

经典 VS Code 活动栏（Activity Bar）+ 右侧可选双栏

最像原生 VS Code / Cursor：最左 44px 图标活动栏切换「项目会话 / 资源管理器 / Git / 搜索 / 定时任务」，文件树既可放左边也可放右边
💡 试试交互：点击最左侧 44px 活动栏的 5 个图标（会话树 / 文件资源管理器 / 源代码管理 Git / 收件箱 / 定时任务），或者点击文件面板右上角的「移到右侧并排 ◨」按钮切换单侧栏 / 双侧栏！

核心设计要点

  • 最左 44px Activity Bar：固定展示核心视图图标 + 待处理数字角标 + 底部账户与设置（和 VS Code 肌肉记忆 100% 一致）。
  • 文件树包含两个折叠子区：完全照搬 VS Code 资源管理器的 OPEN EDITORS（打开的会话与文件） + 项目文件夹树，顶部带项目下拉切换器。
  • 支持「移到右侧辅助侧栏（Secondary Side Bar）」：窄屏时左边切视图就够用，完全不用开右栏；大屏点一下 ◨ 把文件树钉去右边，和会话同屏。

优势

  • 窄屏 / 笔记本极度友好：1280px 屏幕下不用开右侧抽屉，直接在左边切一下图标就能看完整文件树和 Git。
  • 扩展性极强：以后加「工作流库」「插件市场」「远程设备」只需在活动栏多一个图标。

注意点与工作量

  • 刚在 2026-11 去掉了左侧窄栏合成单栏（03-ui-layout.md §1），这个方案等于重新引入 44px 活动栏。
  • 在左边切到「文件树」时，如果不把文件树移到右边，就看不到跨项目的会话状态了。
  • 工作量约 5–6 天（需调整 DesktopShell 外壳布局与视图路由）。
方案 C

左侧上下分栏（项目树 + 当前项目文件树）· 右侧专注运行时

参考 VS Code 多段式 Explorer（Outline / Timeline 上下分栏）：左边上半部分选项目/会话，下半部分直接展开当前项目文件树
💡 试试交互：左侧上半区切换项目（NextCoWork / Octopus / Agent），看左下角的文件树跟着当前项目自动切换！右侧检查器只保留纯粹的 AI / 开发运行时面板（改动审查 Diff、Git 提交、终端、子代理）。

核心设计要点

  • 导航全部收归左侧：左栏内像 VS Code Explorer 的上下可拖拽 SplitView —— 上半区是 项目与会话，下半区是 文件资源管理器 · {当前项目}。
  • 默认两栏就能干所有活：关掉右侧检查器（⌘⌥I）时，依然能同时看到「项目会话列表 + 文件树 + 中间主工作区」，主工作区非常宽敞。
  • 右侧回归纯粹「检查器」：右侧去掉文件树，只放「本轮 AI 改动审查（Diff）」「Git」「终端」「子代理监控」。

优势

  • 心智模型非常干净：「左边 = 找东西（找项目、找会话、找文件）」，「中间 = 干活（聊 AI、看代码）」，「右边 = 查状态（看改动 Diff、跑终端）」。
  • 不需要开第三栏就能边聊 AI 边点开项目文件。

注意点与工作量

  • 纵向空间竞争：左栏高度有限（比如 800px 高的屏幕），项目多 + 文件目录深时，上下两个滚动区会显得有点挤（需要靠折叠和拖拽分隔条平衡）。
  • 工作量约 4–5 天（把 FilesPane 迁入左侧可调比例的下方面板，调整 InspectorTabs 默认页签为审查/Git）。
