左侧菜单重设计 · 四个方案

左侧区域现在由两栏组成:64px 的项目栏和 288px 的项目面板。下面先列出它现在的问题,再给出四个可以直接点的方案,每个都用同一份模拟数据(5 个项目、1 个项目组、3 项待处理、2 个运行中)。选定一个后告诉我,我会先改 docs/design/03-ui-layout.md §1,再动手实现。

主题
现状A 精修两栏B 单栏项目树C 活动栏D 会话时间线对比

现状整理:左侧有哪些问题

坏
项目名旁的 ⌄ 点了没反应。按钮没有绑定命令,像菜单却打不开。
坏
「终端和智能体」的 + 和每一行点了都没反应。同样没有绑定命令。
中
别的项目在等你,只能看到一个数字角标。看不出是哪个会话、要你做什么,只能一个个点进去找。
中
最常用的「新会话」是分区标题后面一个 14px 的 +。新用户很难找到。
中
会话行信息太少。只有状态点和时间,看不到运行了多久、有几项待批、是否失败;也没有「今天 / 更早」的分组,旧会话会把列表越拉越长。
中
「当前在哪个项目」重复说了三遍。项目栏的选中环、面板顶部的大字项目名、整行等宽字体的路径,占掉面板顶部约 110px。
小
「在此项目中搜索」和 ⌘K 面板重复。前者只筛选会话标题,名字却像全文搜索。
小
「自动化」分区下只有一项「定时任务」。一个分区标题加一行,比较浪费。
小
「显示已归档」是一个没有文字的归档图标。打开后状态不明显。
小
账户和设置挤在 64px 项目栏底部,只有图标。登录状态要靠头像上的小点判断。
A

精修两栏

保留「项目栏 + 项目面板」的骨架,只修问题、补信息
可以点:左边的项目图标、项目名(打开项目菜单)、会话、「更早」、终端分区的 +、待处理卡片里的「其他项目」。

怎么变

  • 项目名 ⌄ 变成真正的项目菜单:切换项目、在访达中显示、复制路径、更改图标、项目设置。路径从常驻行挪到菜单和悬停提示里。
  • 「新会话 ⌘N」做成一整行按钮,旁边是 ⌘K 搜索。面板里的「在此项目中搜索」框去掉。
  • 这个项目有待处理时,顶部出现黄色卡片;卡片底部写着「其他项目还有 N 项」,点一下跳过去。
  • 会话按置顶 / 今天 / 昨天 / 更早分组,「更早」默认收起。行尾依次显示待处理数 → 运行计时 → 时间。
  • 「定时任务」和「已归档」挪到面板底栏。

好处

  • 改动最小:项目栏、项目组、拖放全部不动,用户不用重新学习。
  • 修掉三个点了没反应的按钮。
  • 面板顶部从约 110px 缩到 70px,会话能多显示 2–3 行。

代价

  • 跨项目的情况仍然只有角标和一行提示,在多个项目之间来回处理审批还是要多点几下。
  • 左侧总宽仍是 64 + 288px。
  • 工作量:2–3 天。主要改 ProjectPanel.axaml、SessionRow 和 ProjectPanelViewModel 的分组逻辑。
B

单栏项目树

推荐去掉两栏,合成一栏:顶部放全局入口,下面所有项目可以就地展开看会话
可以点:项目行(展开 / 收起)、「工作」组标题、会话、「显示更多」、悬停项目时出现的 + 和 ⋯、左上角的 ◧(⌘B 收起后变成现在的图标栏)。

怎么变

  • 顶部 4 个全局入口:新会话 ⌘N、搜索 ⌘K、收件箱(角标 = 所有项目的待处理数,等同 ⌘J)、定时任务。
  • 下面是项目树:项目组 → 项目 → 会话和终端。收起的项目在行尾汇总状态(待处理数 / 运行中 / 离线);展开的项目先列需要你处理和运行中的会话,其余按时间排列,最多显示 4 条,多的收进「显示更多」。
  • 设备只在非本机时写在项目名后面(和刚做的「单设备不显示设备」一致)。
  • 底部:头像、名字、登录状态、设置。
  • ⌘B 收起后变成 60px 的图标栏,就是现在的项目栏(带角标和项目组胶囊),原有代码可以复用。

好处

  • 一眼看到所有项目的状态:哪个会话在等你、哪个在跑,不用逐个切换。
  • 切换会话(包括跨项目)只要点一下;现在跨项目要先点项目再点会话。
  • 左侧总宽从 352px 降到约 280px,工作区更宽。
  • 和 Codex、Claude 桌面版、Cursor 的心智一致,上手快。

代价

  • 项目一多(20+)时树会变长,靠「收起的项目只占一行」和项目组折叠来控制。
  • 拖放规则要从图标栏搬到树里(RailDropPlanner 的纯函数可以复用,命中区域要重算)。
  • 03 §1 的「三栏」描述要重写;项目面板头部的分支、工作区状态挪到会话标签栏或右侧 Git 页签。
  • 工作量:5–7 天。
C

活动栏 + 面板

左边窄栏不再放项目,改成「模式」切换(类似 VS Code / Slack)
可以点:左侧四个模式、顶部的项目切换框、收件箱里的允许 / 拒绝、运行中的停止。

怎么变

  • 52px 活动栏放四个模式:会话、收件箱(黄色角标)、运行中(蓝色角标)、自动化。头像和设置在底部。
  • 「会话」模式:顶部一个项目切换框(可搜索、按组列出、带状态),下面是这个项目的会话和终端。
  • 「收件箱」模式:跨项目的审批和问题卡片,可以直接允许或拒绝,不用进会话。
  • 「运行中」:所有在跑的 Run,带计时和停止按钮。「自动化」:定时任务列表。

好处

  • 处理审批最快:在收件箱里一屏处理完,适合同时开很多 Agent 的重度用户。
  • 每个模式有专属的空间,以后加「插件」「设备」等模式不会挤。

代价

  • 项目图标不再常驻,切换项目要两次点击(⌘1–9 和 ⌘K 仍可用)。项目组的 2×2 网格、拖放排序只能放进切换框里,存在感变弱。
  • 直接在列表里点「允许」,看不到上下文,只适合低风险操作;高风险的仍要跳进会话。
  • 工作量:6–8 天。
D

会话时间线

以会话为中心:所有项目的会话混在一条时间线里,项目只是一个筛选条件
可以点:顶部的项目筛选 chip、会话、「新会话 ▾」(会先问在哪个项目里新建)。

怎么变

  • 一列会话,分成需要你 / 运行中 / 今天 / 昨天 / 更早五组;每行前面有一个很小的项目图标。
  • 顶部的 chip 按项目筛选,chip 上有这个项目的待处理数。
  • 新建会话时选择项目,默认是当前筛选的项目。
  • 项目管理(添加、分组、图标)挪到设置里,或者放进 chip 的右键菜单。

好处

  • 最简洁:一个列表,最重要的永远在最上面。
  • 适合「项目少、会话多」的用户,以及跨项目干活的人。

代价

  • 项目、项目组这一层几乎消失,和 03 里花了很多设计的项目栏、分组、拖放、项目图标相冲突。
  • 终端、定时任务这些按项目归属的东西没有自然的位置。
  • 项目多了,chip 一行放不下。
  • 工作量:4–5 天,但要删掉 / 搬走的现有功能最多。

不管选哪个都要做的

  • 修好点了没反应的按钮:项目名 ⌄、终端分区的 +、终端行。
  • 会话行补全状态:行尾显示待处理数(黄)、运行计时(蓝)、失败(红),优先级依次降低,只显示一个。数据来自已有的 ActivityInboxView 和 SessionActivityView,不新增真源。
  • 会话按时间分组:分组逻辑写成 Ncw.Core/Domain 里的纯函数,手机端的会话列表一起用。
  • 「新会话」做成显眼的按钮。项目内搜索并入 ⌘K。
  • 所有新文字走 NcwTextKind + 两份 xlf;颜色全用 Arc token(这个页面里的颜色也都是按 token 名写的)。

我的推荐是 B:它把「左侧最该回答的问题」——哪里在等我、哪里在跑——直接摆在眼前,而且 ⌘B 收起后就是现在的图标栏,老用户的习惯没有丢。如果想尽快见效、风险最低,选 A。回复「选 A / B / C / D」即可,也可以组合,比如「B,但收件箱用 C 的卡片样式」。
